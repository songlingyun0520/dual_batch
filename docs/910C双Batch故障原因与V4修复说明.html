故障复盘 · ASCEND 910C · 2026.10.20

双 Batch 推理退出：原因与 V4 修复

DeepSeek V3.2 W8A8 · 16 卡 · DP2 / TP8 / EP。围绕一次“实际 7 个 decode token，输入容量补齐到 113”的布局冲突，说明失败原因、修复边界与当前验证进展。

vLLM 0.23.0enable_mlapo = falseFULL_DECODE_ONLY图容量 4 / 8 / 12 / 16V4 提交 01cc190
根因：V3 把 DecodeOnly 状态等同于“每个输入 token 都有一行请求 metadata”。

跨 DP 协调后，输入 token 容量可能扩大，而本步在非图模式下保留紧凑的请求 metadata。V3 仍尝试按 token 行拆分请求，触发布局校验并退出。V4 在计算开始前识别此布局，使该非图步骤执行原始完整 batch 流程；标准 decode 图继续使用双 batch。

02

为什么 7 条请求会遇到容量 113？

113 输入 token 行容量
实际 token：7补齐位置：106
7 请求 metadata 行（V4 日志确认）
请求 1234567

seq_lens、cum_query_lens、block_table 描述请求；它们的行数不必在非图步骤中扩展到输入容量。

失败轮次的调度器记录：7 条运行请求，每条调度 1 个 token，总共 7 个。跨 DP 同步代码允许扩大输入 token 容量；当执行回落到 NONE 时，请求级 metadata 可以继续保持紧凑布局。V3 没有区分这种情况与标准的 uniform decode 图布局。

113 表示输入容量。它不代表 113 条请求，也不代表历史 KV 长度。日志未提供对端 DP 同一步的完整调度内容，因此不能进一步断言“113 是对端多少个 prefill 与 decode token 的和”。
RuntimeError: SFA dual decode requires one request row per query token,
including graph padding; capacity=113,
mismatched tensors=['seq_lens', 'cum_query_lens', 'block_table']

物理 KV cache 本身不需要随这种请求行切片搬家。直接删除校验、把请求行强行解释成 113 行，会让子 batch 的请求与 cache 映射失去正确对应。

03

V4：按本步真实布局选择执行路径

本步条件V4 执行方式保留的边界
标准 DecodeOnly 布局，请求行与输入 token 行对应。保留 A/B 拆分，attention KV/Q 准备后移。标准 decode 图仍使用原定双 batch 顺序。
DP > 1；紧凑 metadata；运行时图模式为 NONE。在 QKV 与 cache 写入前选择原始完整 batch 流程；本步同时关闭拆分与后移。保留所有 token padding、原 metadata、cache 地址和原通信边界。
紧凑 metadata 出现在 FULL / PIECEWISE 运行时。明确报错。不将不符合要求的布局捕获到图中。
其他不支持的配置或不一致的 metadata。保留原保护校验。没有通过删除校验掩盖错误。

标准双 batch 的目标顺序

A：QKV / q_c 归一化 / Indexer K 与 cache → LI A
B：QKV / q_c 归一化 / Indexer K 与 cache → LI B
合并投影中间结果 → 完整 batch attention KV/Q 准备
SFA A → SFA B → 合并输出
完整 batch V / O / 通信 → MoE

仅当前非图步骤回退

V4 不改变 FULL_DECODE_ONLY 启动配置。遇到紧凑请求布局时，该步走完整 batch；后续符合条件的步骤继续使用已有图。

回退不是为 113 行输入新建双 batch 图，也不把 7 条真实请求复制成 113 条。

V4 未实现 KV offload、miss KV 搬运或新的跨流 overlap。硬件实际双 batch 算子顺序，仍需 profiler 核验。

展开：回退条件与代码入口
  • _SFA_DUAL_BATCH 开启，且当前状态为 DecodeOnly，DP 数大于 1。
  • 0 ≤ num_actual_tokens ≤ request_rows < num_input_tokens。
  • 三组请求 metadata 行数一致；slot_mapping / cos / sin 覆盖输入容量。
  • get_forward_context().cudagraph_runtime_mode == CUDAGraphMode.NONE。
  • 在 QKV 前将 defer_attention_prepare=False，使双 batch 分支与后移分支本步均不进入；打印 warning_once 日志。

判断读取主机计数与 tensor 形状，不通过 .item() 读取设备长度值。代码：V4 sfa_v1.py。

部署与复测

  1. 下载 V4 安装必需两文件包，把解压后的文件夹放到 Docker 的 /workspace/sfa_patch_v4。
  2. 停止服务及全部 worker。V4 的安装器和源码必须配套，实际运行目录里的旧源码交给安装器备份替换。
cd /workspace/sfa_patch_v4
python apply_combined_patch.py
python apply_combined_patch.py --apply

继续使用原启动命令，保留以下配置并重启全部 worker 重新捕图：

export VLLM_ASCEND_SFA_DUAL_BATCH=1
export VLLM_ASCEND_SFA_DEFER_ATTN_PREP=1

# 原 vllm serve 命令中的参数
--additional-config '{"enable_mlapo":false}'
--compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY","cudagraph_capture_sizes":[4,8,12,16]}'

先确认 benchmark 完整结束，再按 start_profile → benchmark → stop_profile 采样。安装备份名为 sfa_v1.py.before_dual_defer_v4；需要回退时停止服务、恢复备份并重启。完整文件与说明：stage2_dualbatchpatch_v4。
